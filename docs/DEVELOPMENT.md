# TRAIN LIVE 開發紀錄

台鐵即時時刻表網頁：直接顯示「加上誤點後的實際時間」，並依實際發車順序排列。
正式網址：https://benjamindai-train-app.vercel.app

這份文件整理 2026/10/26–28 的大改版：做了什麼、為什麼這樣做、怎麼確認、還有什麼沒做。
之後改東西前先看一下「設計原則」和「已知限制」，避免把討論過的決定改回去。

---

## 1. 架構

```
手機瀏覽器 ──> Vercel（香港 hkg1）
                ├─ public/index.html   前端畫面（HTML）
                ├─ public/style.css    樣式
                ├─ public/stations.js  縣市 → 車站清單
                ├─ public/app.js       前端程式
                ├─ public/sw.js        Service worker（離線開啟網頁）
                └─ api/index.py        後端 API（Python serverless）
                      ├─> TDX 運輸資料流通服務（台灣）  時刻表、誤點、營運通阻、車站
                      └─> Upstash Redis（東京 ap-northeast-1）  快取、回報、管理員登入
```

| 檔案 | 內容 |
|---|---|
| `api/index.py` | 查詢 API、使用者回報、開發者後台（god mode）API |
| `api/stations.py` | 站名 → TDX 站碼（`STATION_MAP`） |
| `public/index.html` | 前端畫面（HTML），依序載入下面三個檔案 |
| `public/style.css` | 所有樣式 |
| `public/stations.js` | 縣市 → 車站清單（`STATION_DATA`） |
| `public/app.js` | 前端程式（查詢、列表、選單、教學、後台） |
| `public/sw.js` | 把網頁、字型、圖示存在手機裡；HTML／CSS／JS 一律先抓最新的，避免新舊版混用 |
| `public/fonts/` | Barlow Semi Condensed（只含英數符號，各約 36 KB） |
| `vercel.json` | `/api/*` 轉到 `api/index.py`；`regions: ["hkg1"]` |

### 環境變數（Vercel → Settings → Environment Variables）

| 名稱 | 用途 |
|---|---|
| `TDX_ID`、`TDX_SECRET` | TDX 帳號（免費方案，有呼叫頻率上限） |
| `ADMIN_PASS` | 開發者後台密碼（只需要密碼，沒有帳號） |
| `UPSTASH_REDIS_KV_URL` | Redis 連線字串（由 Vercel Storage 的 Upstash 整合自動產生，prefix 設 `UPSTASH_REDIS`） |

`ADMIN_USER` 已經不用了，可以刪除。

## 2. 後端

### 一次查詢的流程（`GET /api/index?start=&end=&next_day=&mode=`）
1. **一次 Redis 往返**：同時讀快取（TDX token、誤點、營運公告、時刻表）並把這個 IP 的查詢次數 +1。
2. 超過每分鐘查詢上限 → 回 429。
3. 快取沒有的才去打 TDX；token 只有真的要打 TDX 才拿。
4. 過濾停駛班次、套上誤點、依實際發車時間排序。
5. 回傳班次、營運公告、被隱藏的停駛班次數。

### 快取與限制

| 項目 | 數值 | 原因 |
|---|---|---|
| 時刻表快取 | 2 小時 | TDX 時刻表約 4 小時才更新，更短只是多打 TDX |
| 誤點快取 | 2 分鐘 | 列車經過報點站才更新；免費帳號每月約 4,400 次，要省著用 |
| 營運公告快取 | 10 分鐘（失敗時 5 分鐘內不重試） | 公告平常很少變，而且 TDX 公告本身常常比實際慢 |
| Vercel CDN | 60 秒 | 相同網址直接由 CDN 回應 |
| 每個 IP 查詢上限 | 每分鐘 40 次 | 防止繞過前端限制、用光 TDX 額度；宿舍共用 IP 也夠 |
| TDX 回 429 | 等 0.8 秒重試一次 | 免費帳號有頻率上限；只重試一次 |
| TDX 逾時 | 連線 3 秒、讀取 8 秒 | TDX 卡住時不要一直等 |

前端另外還有：每分鐘最多查詢 3 次、更新按鈕冷卻 30 秒（存在瀏覽器，只是體驗上的限制，真正的保護在後端）。

### 停駛與營運異常（兩種方法一起用）
1. **停駛標記**：TDX 時刻表每班車的 `TrainInfo.SuspendedFlag`（0 正常、1 停駛、2 部分停駛）。
   部分停駛時看出發站／抵達站那一站 `StopTimes[].SuspendedFlag`。已用真實資料確認欄位存在。
2. **營運通阻公告**：`/v3/Rail/TRA/Alert`（失敗退回 v2）。`Status: 1` 或標題含「營運正常」不顯示；其他顯示成黃色橫幅，一律展開不收合（標題＋完整內文＋台鐵公告連結）。

為什麼兩個都要：TDX 時刻表約 4 小時才更新，臨時停駛（颱風、事故、設備故障、地震）會有時間差，要靠公告即時告知。

**已驗證**（2026-10-30 光復～富源號誌故障）：異常公告能正確解析並顯示，標題「號誌故障」，內文「光復 <--> 富源 : …」，連結指向台鐵通阻公告頁，與 e訂通推播文字一致。

### 站碼
- `stations.py` 曾經有兩段整段錯位（手打時漏站，後面全部差一號）：
  - 大湖～三塊厝（新左營被當成楠梓）
  - 宜蘭線冬山～三貂嶺（漏了新馬 7140）
  - 內灣／六家線全錯
- 2026/10/27 已全部依官方站碼修正，並補上新馬、平鎮；「侯硐」改為官方寫法「猴硐」（舊設定會自動轉換）。
- 用後台「**檢查站碼**」可以直接跟 TDX 官方車站資料比對。官方有但程式沒有的這幾個不用加：
  南方小站 5998、潮州基地 5999（車輛基地）、臺北-環島 1001（環島列車）、枋野 5170（號誌站）。
- 新增車站時，`api/stations.py` 和 `public/stations.js` 的 `STATION_DATA` **兩邊都要加**。

### 開發者後台（god mode）
- 進入：在首頁連點左上角「TRAIN LIVE」5 下 → 輸入密碼（時刻表裡點 LOGO 是回首頁）。
- 功能：看／清空使用者回報、**檢查 TDX**、**檢查站碼**。
- 安全性：
  - 密碼只在登入時用 POST 傳一次，之後用伺服器發的隨機 token（30 分鐘，Redis 只存雜湊值）
  - 同一 IP 錯 5 次鎖 15 分鐘，全部 IP 合計 30 次
  - `hmac.compare_digest` 比對；沒設定 `ADMIN_PASS` 時後台直接關閉
  - 只能讀 `report:` 開頭的資料；後台 API 不開放跨網域、不快取
- 使用者回報：單筆最多 32 KB、同一 IP 10 分鐘最多 20 筆、保留 7 天。
- 「檢查 TDX」每按一次會直接打 TDX 好幾次（不走快取），不要連續狂按，會撞到 429。

### 「檢查 TDX」怎麼看

| 欄位 | 正常值 |
|---|---|
| `server_region` | `hkg1` |
| `redis_ms` | 約 100（香港 ↔ 東京） |
| `tdx_ms` | 幾十到一百多 |
| `timetable_status` | 200（429 = 太頻繁，等一兩分鐘） |
| `suspended_flag_counts` | 有數字；出現「沒有這個欄位」代表 TDX 改了格式 |
| `alert_parsed` | 營運正常時是空的 |

## 3. 前端設計原則

這些是一來一往討論後定下來的，改之前先想一下原因：

- **配色不變**：黑底、`#4d7f5e` 綠、`#e6b800` 黃（誤點）、車種色（區間藍、自強紅、普悠瑪暗紅）。
- **不要「AI 感」**：不用 emoji 當圖示、不用漸層、不要每個東西都包圓角框、不要呼吸燈／跳動動畫。按鈕用小圓角（3px）。
- **字體**：數字和英文用 Barlow Semi Condensed（車站看板感），中文用系統字。比較過的其他選項（Inter、JetBrains Mono、粉圓）在 `design/font-test` 分支。
- **起訖站**：兩個大站名＋綠色路線線條（實心圓起站、空心圓迄站，線條從圓心連到圓心）。不寫「選擇起站」「起／迄」這類字。
- **選站畫面**：左邊縣市、右邊車站清單；大站白字、小站灰字；目前的站是淡綠底＋左側綠線＋打勾（不用漸層，不用整行實心綠）。
- **查詢／更新是同一顆按鈕**：換站後是「查詢」，查過同一條路線變「更新」；冷卻中或次數用完變灰並倒數。不會自動查詢（會消耗次數）。
- **班次列表（B 版）**：細線分隔＋左側車種色條；車種在上、時間在下；誤點時出發和抵達都變黃，右邊「晚 N 分」下面接「原定 HH:MM」，每班高度一致、不留空白。準點右邊不寫字。
- **10 分鐘內發車**：左邊兩顆交替閃爍的綠燈（使用者很喜歡這個設計，保留）。
- **更新時間**併在列表第一行左邊，右邊是「顯示 N 班已發車」（有箭頭，看得出能按）。
- **首頁**：每次打開都先到首頁，不會自動帶上次的路線。上面是空白的出發／抵達，下面是收藏路線，點一下直接進時刻表並查詢（使用者自己點的，不算自動查詢）。沒有收藏時只寫「目前無收藏路線」。右上「編輯」可以拖曳排序、刪除。
- **收藏**：時刻表站名右邊是「＋｜收藏」連在一起的框。按 ＋ 直接收藏，已收藏變綠色打勾，再按一次取消（下面出現「復原」6 秒，可以滑掉）。按「收藏」點開列出收藏路線；目前路線綠字，還沒收藏就多一行「＋ 收藏這條路線」。首頁收藏往左滑露出「刪除」要再按一下才刪；編輯模式也能刪。刪除不跳確認視窗，用「復原」代替。最多 6 條，來回兩個方向分開存。不記查詢紀錄（2026/10/30 拿掉，收藏可以自己排序就夠了）。
- **回首頁**：時刻表左上角「‹ TRAIN LIVE」或手機返回鍵。開發者後台只有在首頁連點 LOGO 5 下才會出現。
- **動畫**：只做短（0.2～0.35 秒）、安靜的過場，系統開「減少動態效果」就全部不播。點收藏進時刻表，站名從那一行平移放大到上方；按查詢進去，整組站名移到左上；回首頁從左邊滑回來（從左邊緣滑回時不重播）；交換鍵讓兩個站名交叉換位；查到班次列表依序淡入；收藏選單往下展開；刪收藏那一行先收起來；按鈕按下縮一點。
- **教學**：第一次查到班次後出現一次，3 步，用示範班次（不靠真實資料，保證看得到誤點和綠燈），選單「教學」可重看。文字要短。
- **選單**：教學／時間／回報／關於／分享，字越少越好。
- **關於**：作者寫「BenjaminDai · Claude · Gemini」，BenjaminDai 綠色並連到 IG。
- **離線**：沒網路時顯示這條路線最後一次的結果並標註時間；網路恢復自動更新一次。

## 4. 開發流程

1. 從 `main` 開新分支（`fix/…`、`feature/…`、`perf/…`、`design/…`）
2. 推上 GitHub → Vercel 自動產生**預覽網址**，先在手機上試
3. 開 PR，說明改了什麼、怎麼測
4. 用 **squash** 合併到 `main` → Vercel 自動部署正式版
5. 上線後用後台「檢查 TDX」／「檢查站碼」確認

介面的改動先做示意圖或預覽版確認，再改程式。

Vercel 預覽網址可能需要登入 Vercel 才看得到；要給朋友看的東西要另外處理。
